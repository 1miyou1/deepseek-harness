# Agent Note: 新增通用文档整理模块

Status: implemented

[English](2026-09-06-document-organizer-module.md) | 中文

## 问题

仓库文档需要一个有边界的整理器，以更新已有 Markdown、新建文档和移动文档；日常编辑工作不应分配给 Sol 级模型，模型失败后也不应留下部分文件改动。

## 决策

profile 将 `document-organizer@1.0.0` 注册为可选的 Agent 发起模块。每次运行接收明确的仓库相对 Markdown 或双语 sidecar 路径列表和整理任务。模块拒绝归档 Agent Note、绝对路径、路径穿越、符号链接、敏感路径、声明集合以外的文件。

模块让一个全新受管子 Agent 生成结构化变更计划，并显式选择配置的 Luna 路由。如果该子 Agent 以运行时的模型或传输错误结果结束，模块使用配置的 Terra 路由重试一次。模块绝不选择 Sol。路径校验、无效结构化输出、取消、文件系统失败和文档门禁失败都不会触发降级。

规划子 Agent 的提示词只包含声明的文件内容，不提供任何工具。结果列出写前比较更新、新文件和保持内容不变的移动操作。Host 在修改前验证每个操作，使用回滚副本应用完整计划，然后运行 Agent Note、翻译配对和 Markdown 链接检查；任何操作或检查失败时，Host 恢复原文件并删除新建目标。

模块通过已校验的部署配置限制文件数量、输入总字节、计划字节、Agent 步数、每步输出 token、子进程输出和总运行时间。结果报告所用路由、是否降级、变更路径和针对性检查结果。

## 考虑过的替代方案

**让 Agent 直接编辑。** Luna 失败时可能留下部分移动或写入操作供 Terra 接手，因此模型只生成计划。

**始终使用 Terra 或 Sol。** 日常分类、重组和改写不值得使用更高成本路由。Terra 只保留为一次降级，Sol 被排除。

**自动扫描所有 Git 改动。** 自动发现可能在脏工作区吸收无关工作，因此调用方必须显式提供完整文件集合。

## 验证

测试证明显式选择 Luna、受管模型错误时只降级一次到 Terra、绝不使用 Sol、校验或文件系统失败时不降级、路径和归档拒绝、写前比较、新建和移动处理、回滚、取消、有界输出、生命周期释放及针对性文档检查。

可选 profile patch 默认不加载该模块。包 README 双语页记录模型、token、KV cache、修改、回滚和已知上限行为，并且所有受影响的文档门禁通过。

## 后果

当前受管子 Agent 结果把模型和传输失败压缩为同一个 `error` 停止原因，因此降级可以把这一类错误与校验和 Host 错误区分开，但不能进一步识别具体的 provider 中断。多文件回滚可以保护仓库内容，但它不是文件系统事务；受控取消以外的进程终止仍可能打断恢复。
